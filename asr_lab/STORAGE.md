# ASR 实验资产保留策略

实验台把“能重新生成的本机内容”和“重现实验所需的证据”分开。目录定义以
`storage-layout.json` 为机器可读事实来源，本文解释为什么这样划分。

| 目录 | Git 策略 | 用途 |
| --- | --- | --- |
| `models/cache/` | 忽略 | 下载的模型权重和 Runtime 载荷，通常体积很大 |
| `models/manifests/` | 保留 | 模型标识、来源、版本、大小和文件摘要 |
| `corpus/source/` | 保留 | 许可明确且纳入固定语料版本的原始音频 |
| `corpus/manifests/` | 保留 | 样本清单、参考文本、标签和许可信息 |
| `corpus/derived/` | 忽略 | 从原始音频确定性生成的预处理文件 |
| `tmp/` | 忽略 | 未完成运行、草稿和中间结果 |
| `reports/` | 保留 | 审核后需要比较和复盘的 JSON、JSONL、Markdown 报告 |
| `logs/` | 忽略 | 可重新产生的详细诊断日志 |

“忽略”避免日常 `git add` 误收大文件，不等于备份。模型可以重新下载，派生音频可以从源文件重建，临时文件和日志允许删除。模型缓存的精确身份不能只靠目录名，因此后续下载模型时仍要在 `models/manifests/` 保存来源、版本和摘要。

“保留”也不表示任何文件都能直接提交。语料必须先确认来源许可；报告必须从临时目录晋升到 `reports/`，并包含足以关联运行环境和输入的标识。运行标识将在任务 1.6 定义。

可以在 `asr_lab/src` 运行以下测试验证边界：

```powershell
python -m unittest discover -s '..\tests' -p 'test_storage_layout.py' -v
```

测试会同时检查应忽略和应保留的代表路径。这样 `.gitignore` 以后若被误改，测试会直接失败。
